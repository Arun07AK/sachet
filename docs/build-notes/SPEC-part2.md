# Sachet build spec, part 2 (internal, for the code generator)

Part 1 (SPEC.md) is implemented: models, domains, extract, redflags, gateway, tools, checks,
planner, scoring, tests. Read those files first. Keep their public APIs. No em dash characters
anywhere (code, comments, docs, UI). Python 3.10+. Tests must stay fully offline.

## Fixes to existing code
1. planner.py: an LLM finding must have at least one source and every source URL must be in
   gateway.seen_urls, otherwise drop it. Record dropped LLM findings count in the report
   (`Report` may gain `dropped_llm_findings: int = 0`, include it in to_dict).
2. planner.py: when the official domain is unknown after footprint, a corporate (non free-mail,
   non third-party) email or URL domain in the offer should be added to ctx.suspicious_domains
   and trigger domain_probe (step reason: "official site not found, probing recruiter domain").
   Mark replan-added steps with added_by="replan" (including moved contact_trace).
3. checks.contact_trace: for Indian phones search `"98765 43210" OR "9876543210"` (spaced and
   unspaced 10 digit forms) instead of the +91 display form.
4. Agent.run: if a gateway was injected, respect the `budget` argument by setting
   gateway.budget = budget unless budget is None.
5. Each step event should also carry `"searches_left": gateway.remaining`.

## New modules

### src/sachet/llm.py (optional, off by default)
OpenAI-compatible chat-completions client using httpx (no openai SDK). Config from env:
`SACHET_LLM_BASE_URL` (default https://api.openai.com/v1), `SACHET_LLM_API_KEY`,
`SACHET_LLM_MODEL` (default gpt-4o-mini). Works with OpenAI, Groq, Gemini's OpenAI endpoint,
OpenRouter, or local Ollama (http://localhost:11434/v1, key optional).
`class LLM` with:
- `from_env() -> LLM | None` (None when no key and base url is not localhost).
- `refine(offer) -> Offer`: ask for strict JSON {company, role, city, address} from the raw text,
  fill only fields the rules left empty; never overwrite emails/phones/pay/fees.
- `investigate(ctx) -> list[Finding]`: tool-calling loop using `ctx.tools.openai_tool_schemas()`
  and `ctx.tools.call_tool`. System prompt: you are a careful fraud investigator for Indian job
  offers; you get the extracted entities, the findings so far and the remaining search budget;
  make at most `min(3, gateway.remaining)` tool calls to close the most important open
  question; then reply with JSON {"findings": [{"severity": "high|medium|low|info|positive",
  "title": str, "detail": str, "source_urls": [str]}]}. Map to Finding(check="agent",
  origin="llm", sources built from URLs, titles looked up from gateway responses if possible).
  Stop on BudgetExceeded. Max 6 loop turns. Handle malformed JSON by returning [].
- `summarize(report) -> str`: 2 to 3 sentence plain summary grounded only in findings.
Timeouts 60s; any HTTP error returns the rule-based result (never crash the run).
Unit tests with httpx.MockTransport (inject transport via ctor).

### src/sachet/report.py
- `to_markdown(report) -> str`: verdict line with score, summary, findings grouped by severity
  with source links, the step log is not needed here, searches used (live vs cached), next
  steps, and a footer "Generated by Sachet using live SerpApi results".
- `to_terminal(report, color=True) -> str`: compact ANSI rendering (no external deps).

### src/sachet/cli.py
`sachet check [FILE|-] [--budget N] [--json] [--markdown] [--replay DIR] [--record DIR]
[--no-cache] [--llm] [--verbose]` prints live progress lines to stderr as events arrive
("search google: ...", "step footprint: done") and the report to stdout. Exit code 0 always
except bad usage (2) or missing key in live mode (3, with a message telling the user to set
SERPAPI_API_KEY, free key at https://serpapi.com/users/sign_up).
`sachet serve [--host 127.0.0.1] [--port 8000] [--replay DIR]` starts the web app.
`sachet examples` lists bundled example offers.

### src/sachet/web.py + src/sachet/static/index.html (+ app.js, style.css)
FastAPI app factory `create_app(replay_dir=None, budget=8)`.
- `GET /` serves index.html. `GET /api/examples` returns examples from `examples/*.txt`
  (resolve relative to repo root or package; also bundle copies under src/sachet/examples/).
- `POST /api/investigate` body {text, budget?, use_llm?} returns a streaming NDJSON response:
  one JSON event per line (extracted, step, search, finding, report, error). Run the agent in a
  worker thread with a queue.
- `GET /api/health` returns {ok, live: bool (key present), replay: bool, llm: bool}.
UI (single page, no build step, vanilla JS, clean modern look, works at 1280x800): header "Sachet"
with tagline "Check a job offer before you pay or share documents". Left: textarea, example
chips, budget selector, Investigate button. Right: live agent timeline (each step with a status
chip, each SerpApi search shown with engine badge and query, cached tag), then a verdict card
with a big score gauge and color (green, amber, red), summary, findings list (severity chip,
title, detail, source links opening in new tab), extracted entities panel, next steps with the
1930 helpline. Show a banner when no key is configured. All text plain, no em dashes.

### src/sachet/mcp_server.py
Optional MCP server (package `mcp`, FastMCP) exposing tool `verify_job_offer(text: str,
budget: int = 6) -> str` returning the markdown report. `main()` runs stdio. Import of `mcp`
must be lazy so the core package works without it; if missing, print how to install
`pip install "sachet[mcp]"` and exit 1.
